# Topic: Data Storage Technologies for Analytics

## Simplified Explanation:

This lesson introduces how data is stored for analytics. After data is captured by source systems, it must be stored in a way that makes analysis efficient and practical.

### Why Not Analyze Data Directly from Source Systems?

Source systems are often not ideal for analytics because:

- They are optimized for business operations (OLTP - Online Transaction Processing), not analysis.
- They contain a lot of unnecessary operational data.
- Direct analysis could slow down or disrupt critical business systems.
- They may not keep historical data for long periods.

Therefore, organizations often move data into separate analytical storage environments such as data warehouses or centralized repositories.

### Two Main Ways to Store Data

1. Data Files

A file system works like a digital filing cabinet where files are organized into folders.

Advantages:

- Can store almost any type of data.
- Supports structured and unstructured data.

Examples:

- Documents
- Images
- Videos
- Audio files
- Spreadsheets

Disadvantages:

- Harder to analyze directly.
- Data often needs preprocessing before analysis.

Hadoop Distributed File System (HDFS)

A large-scale file system designed for big data.

Features:

- Stores huge amounts of data.
- Uses distributed storage across many machines.
- Works with structured and unstructured data.

Common Data File Formats:

- Delimited Text Files

Store data in rows and columns.

Common delimiters:

- Comma (CSV)
- Tab
- Pipe (|)

Benefits:

- Easy to share between systems.
- Widely supported by analytics tools.

XML Files (Extensible Markup Language)

- Used for structured data exchange.
- Common in web and application systems.
- More flexible than text files but harder to analyze.

Log Files
- Capture events generated by systems.
- Common in web analytics, machine monitoring, and messaging systems.
- Often require a parser to read and interpret.

Application-Specific Files

Created by analytical tools such as:

- Microsoft Excel
- SPSS
- SAS
- Tableau

These files often contain both data and metadata (information about the data). Excel remains one of the most widely used analytics tools because of its flexibility and ease of use.

2. Databases

A database is an organized collection of related data managed by a Database Management System (DBMS).

Benefits:

- Stores large amounts of related information.
- Maintains relationships between different datasets.
- Makes querying and retrieval more efficient.

### Types of Databases

Relational Databases (Most Important)

Data is stored in tables consisting of rows and columns.

Key feature:

- Tables are linked through relationships.

Why important?

- Most widely used database type.
- Easy to understand and query.
- Foundation of SQL and data warehousing.

Graph Databases

Designed to analyze relationships between connected entities.

Examples:

- Social networks
- Location networks
- Recommendation systems

Document Stores

Store documents and related metadata.

Good for:

- Unstructured data
- Flexible data formats

Columnar Databases

Store data by columns instead of rows.

Benefit:

- Faster analytical queries and aggregations.

Key-Value Stores

Store data as simple pairs:

Key → Value

Benefits:

- Very fast
- Memory efficient
- Highly scalable

Often used in modern web applications and high-performance systems.

### Quick Comparison:

Storage Type	                          Best For
File Systems	                Storing many different data types
Relational Databases	        Structured business data
Graph Databases	                Relationship analysis
Document Stores	                Unstructured documents
Columnar Databases	            Fast analytics
Key-Value Stores	            High-speed applications

Key Takeaway:

Data for analytics is typically stored in either files or databases. While many storage technologies exist, the Relational Database is the most important for analysts because it organizes data into related tables and serves as the foundation for SQL-based data analysis.



# Topic: Big Data and Cloud Computing

## Simplified Explanation:

This lesson introduces two important concepts in modern analytics: Big Data and Cloud Computing. Although they are often discussed together, they are different concepts.

### Big Data vs Cloud Computing:

Big Data

Big Data refers to:

- Extremely large volumes of data.
- Data generated from sources such as websites, machines, sensors, and applications.
- Technologies used to capture, store, process, and analyze this data.

Traditional tools often struggle to handle this scale of data efficiently.

### Cloud Computing

Cloud Computing refers to:

- Using hardware, software, and services hosted by a third-party provider.
- Renting computing resources instead of owning and maintaining them yourself.

Examples of major cloud providers include:

- Amazon
- Microsoft
- Google

Think of it this way:

- Big Data = What you are doing (working with huge datasets)
- Cloud = Where you are doing it (on rented infrastructure)

You can have Big Data without the Cloud, and you can use the Cloud without Big Data.

### Major Components of a Big Data Environment

1. Data Ingestion and Processing

Before analysis, data must be collected and prepared.

Common tasks:

- Data ingestion
- Data transformation
- Data integration
- Real-time processing

Examples of technologies:

- Hadoop
- Spark
- Kafka
- Hive
- Pig
- NiFi
- Scala

These tools help move and process large amounts of data efficiently.

### Streaming Data

Streaming data arrives continuously in real time.

Example:

- Website clicks
- Sensor readings
- Financial transactions

The instructor compares it to counting fish as they swim past in a river.

Traditional approach:

- Store data first, then analyze later.

Streaming approach:

- Analyze data as it arrives, without storing everything first.

2. Big Data Storage

Large datasets are often stored using:

### HDFS (Hadoop Distributed File System)

- Distributed storage system.
- Stores huge amounts of structured, semi-structured, and unstructured data.
- Uses multiple machines working together.

Often, raw data is stored in HDFS and later moved into more structured databases for analysis.

3. Big Data Analytics

Big Data tools support the same analytics types we learned earlier:

Descriptive Analytics

- What happened?

Predictive Analytics

- What is likely to happen?

Prescriptive Analytics

- What should we do?

The difference is that Big Data tools can perform these analyses on very large datasets and sometimes in real time.

4. Infrastructure

Infrastructure includes:

- Hardware
- Networking
- Security
- Storage systems

Technologies such as:

- Hadoop
- MapReduce

allow organizations to process massive amounts of data using many inexpensive computers working in parallel.

## Cloud Service Models

### SaaS (Software as a Service)

Use software through the internet.

Examples:

- Gmail
- Salesforce
- Microsoft 365

Users focus on using the software, while the provider manages everything else.

### PaaS (Platform as a Service)

Provides a development platform where developers can build applications without managing infrastructure.

Developers focus on coding, while the provider manages the platform.

### IaaS (Infrastructure as a Service)

Provides:

- Computing power
- Storage
- Networking
- Security resources

Organizations can build highly customized environments without owning physical hardware.

### Advantages of Cloud Computing:

- Quick and inexpensive setup.
- Easy scalability.
- Reduced maintenance and administration.
- Built-in backup and disaster recovery.
- Allows companies to focus on their core business.

### Challenges of Cloud Computing:

- Security and privacy concerns.
- Loss of direct control.
- Migration costs from existing systems.
- Dependence on internet connectivity.
- Some organizations have unique requirements better suited to on-premises systems.

### Relationship Between Big Data and Cloud

Many cloud providers offer Big Data services.

Organizations can:

- Run Big Data tools in the cloud.
- Run Big Data tools on their own infrastructure.
- Combine both approaches.

This flexibility allows businesses to choose the solution that best fits their needs.

Key Takeaway:

Big Data focuses on handling massive datasets, while Cloud Computing focuses on where computing resources are hosted. Big Data provides technologies for storing and analyzing large amounts of data, while the Cloud provides scalable and cost-effective infrastructure to run those technologies.



# Topic: Data Virtualization, Data Federation, In-Memory Computing, and In-Database Analytics

## Simplified Explanation:

Traditionally, data is moved from source systems into a central database using an ETL (Extract, Transform, Load) process.

### ETL Process

- Extract data from source systems.
- Transform the data (clean, modify, or reorganize it).
- Load the data into a new database.

This approach works well but has drawbacks:

- Data movement takes time.
- Errors can occur during transfers.
- Data may become outdated before it is available for analysis.
- ETL processing can be resource-intensive.

As technology has improved, new approaches have emerged to reduce data movement and improve analytical performance.

1. Data Virtualization

Data Virtualization makes data appear to be stored in one place, even though it remains in multiple source systems.

Advantages

- No need to duplicate data.
- Changes in source systems become visible immediately.
- Easier access through a single interface.

Limitations

- Additional processing layer can slow queries.
- Complex transformations may reduce performance.
- Does not automatically integrate data from different systems.

2. Data Federation

Data Federation goes a step further than data virtualization.

It:

- Makes data appear to be in one place.
- Integrates data from multiple sources into a common data model.
- Creates relationships between datasets without physically moving data.

Advantages

- Unified view of data.
- No need for large-scale data movement.

Limitations

- More complex processing.
- Can be slower for large or complicated datasets.

### Data Virtualization vs Data Federation

Feature	                       Data Virtualization	           Data Federation
Single access point	                  ✅	                           ✅
Data integration	                  ❌	                           ✅
Physical data movement	              ❌	                           ❌
Complexity	                         Lower	                       Higher

3. In-Memory Computing

Instead of reading data from disk, data is loaded directly into RAM (Random Access Memory).

Benefits:

- Extremely fast access.
- Faster analysis and visualization.
- Ideal for experimentation and trial-and-error analysis.

Drawbacks

- RAM is expensive.
- Large datasets may not fit entirely in memory.
- Initial data loading can take time.

Example

Many modern BI and visualization tools use in-memory computing to provide fast dashboards and interactive analysis.

4. In-Database Analytics

In traditional analytics:

- Data is moved from the database to an analytical tool.

In In-Database Analytics:

- Analytical models run directly inside the database.

Benefits:
- Reduces data movement.
- Faster processing.
- Supports real-time decision making.

Example

A fraud detection model can run directly inside a database and immediately flag suspicious transactions as new data arrives. Even milliseconds can be important in such situations.

### When Are These Approaches Useful?

Data Virtualization / Federation

Best when:

- Data changes frequently.
- Minimal transformation is needed.
- Data already exists in high-quality source systems.

In-Memory Computing

Best when:

- Fast analysis is required.
- Analysts need interactive exploration.

In-Database Analytics

Best when:

- Real-time decisions are critical.
- Predictive models must act immediately on incoming data.

Key Takeaway:

Modern analytics increasingly focuses on reducing data movement and increasing speed. Data Virtualization and Data Federation provide unified access to distributed data, while In-Memory Computing and In-Database Analytics improve performance by bringing data closer to analytical processing or bringing analytics closer to the data.


# Topic: The Relational Database

## Simplified Explanation:

A Relational Database is the most widely used type of database in business. It stores data in tables and creates relationships between those tables. The software used to manage these databases is called a Relational Database Management System (RDBMS). Understanding relational databases is essential because most business data is stored this way, and analysts use SQL to retrieve data from them.

### Basic Structure of a Relational Database

Tables

A table consists of:

- Rows (Records): Individual items or entities.
- Columns (Fields/Attributes): Characteristics that describe those items.

Example:

### FLIGHTS Table

Flight_ID	  Tail_Number	  Departure_Airport	    Arrival_Airport
1001	        N12345	             JFK	             LAX

Each row represents one flight, and each column describes a property of that flight.

### Primary Keys

Every row in a table must be unique.

- A Primary Key (PK) is a column (or group of columns) that uniquely identifies each row.

Types of Primary Keys:

1. Natural Key

Uses existing business information.

Example:

- Tail_Number of an aircraft.

2. Composite Key

Uses multiple columns together.

Example:

- Flight_Number + Departure_Airport + Departure_Time

3. Surrogate Key

An artificial identifier created only for the database.

Example:

- Flight_ID = 1001, 1002, 1003

Most modern databases use surrogate keys because they are simple and reliable.

### Foreign Keys and Relationships

The real power of relational databases comes from linking tables together.

A Foreign Key (FK) is a column that connects one table to another.

Example

PLANES Table

- Tail_Number (Primary Key)
- Aircraft_Type
- Airline

FLIGHTS Table

- Tail_Number (Foreign Key)

Using Tail_Number, the database can connect flight information with aircraft information.

### Logical Data Model

A Logical Data Model is a visual diagram showing:

- Tables
- Primary Keys
- Foreign Keys
- Relationships between tables

Analysts should always try to obtain a data model because it helps them understand:

- What data exists.
- How tables connect.
- How to write effective SQL queries.

### Normalization

Normalization is the process of organizing data into separate tables to reduce duplicate data.

Example

Instead of storing Aircraft_Type in every flight record:

- ❌ FLIGHTS table stores Aircraft_Type repeatedly.

- ✅ Store Aircraft_Type once in the PLANES table and link it using Tail_Number.

Benefits:

- Less storage.
- Easier updates.
- Better data consistency.

### Third Normal Form (3NF)

A database is in Third Normal Form (3NF) when every non-key column directly describes the primary key.

Simple rule:

- Every non-key attribute should describe the key, the whole key, and nothing but the key.

If a column describes something else, it should be moved to another table.

### Advantages of Relational Databases:

- Logical organization of data.
- Reduced data duplication.
- Easier maintenance and updates.
- Good performance for transactions.
- Highly flexible for querying and analysis.

### Disadvantages of Relational Databases

- More normalized databases require more table joins.
- Queries can become complex.
- Adding entirely new types of data can require redesigning the model.

### Denormalization

- Sometimes businesses intentionally combine data to improve reporting performance.

Common Approaches

Database Views

- Virtual tables that combine multiple tables automatically.

Data Marts

- Smaller databases built for specific departments like Finance or Marketing.

Cubes

- Multi-dimensional structures used in Business Intelligence (BI) tools for fast reporting and analysis.

Key Takeaway:

A Relational Database stores data in related tables connected through Primary Keys and Foreign Keys. Good database design uses Normalization (3NF) to reduce duplication and maintain consistency, while Denormalization is sometimes used to improve reporting and analytical performance. Understanding these concepts is critical because SQL-based data analysis depends on knowing how tables and relationships are structured.
